# 网络经济模型

Jetsam 按区块高度固定发行量，硬上限为 21,000,000 JTM，并将持久 State 增长与普通交易处理分别定价。

## 单位

```text
1 JTM = 1,000,000 μJTM
```

JTM 是币种代码；钱包界面中使用符号 ①。
所有共识金额都以 [μJTM](../reference/glossary.md#micro_jtm) 整数表示。

## 区块奖励

初始补贴为 50 JTM。它在七个固定高度减半并恰好归零；没有下限（`jetsam_chain/src/consensus/emission.rs`）：

| 高度范围 | 区块奖励 |
|---:|---:|
| 1 – 28,799 | 50.000000 JTM |
| 28,800 – 172,799 | 25.000000 JTM |
| 172,800 – 831,799 | 12.500000 JTM |
| 831,800 – 1,490,799 | 6.250000 JTM |
| 1,490,800 – 2,149,799 | 3.125000 JTM |
| 2,149,800 – 2,808,799 | 1.562500 JTM |
| 2,808,800 – 3,467,663 | 0.781250 JTM |
| 3,467,664 及以上 | 0 |

最后一个时代被截短 136 个区块，使所有带 coinbase 的高度之和恰为 21,000,000 JTM。创世区块没有 coinbase。减半按区块计数：自区块 38,400 起每天 480 个区块而非 960 个，因此每次减半在日历上更晚到来，而每日发行量在该高度减半。State 扩展（`log_slots`）不再影响补贴；它仍然决定 State 增长费的销毁定价。

## 网络初期开发分配

前两个目标时间年内——区块 1 至 369,600——每个区块补贴按以下比例分配：

- 90% 给矿工；
- 5% 给 Network Fund；
- 5% 给 Lab Fund。

没有预挖。自高度 369,601 起，全部区块补贴归矿工。按计划累计，开发分配总计 747,000 JTM，占最大供应量的 3.56%（`jetsam_chain/src/consensus/development_allocation.rs`）。

为避免每个区块额外创建两个未花费 UTXO，两份开发分配每个目标日通过一条强制双输出[系统记录](../reference/glossary.md#system-record)支付一次：到区块 38,400（含）为止每 960 个区块，之后每 480 个区块。金额采用付款高度处生效的奖励档位。

付款计划、接收者和金额仅由高度无状态地推导，并在 `HistoryStep` 内证明。矿工不能遗漏付款、修改收款方或推迟到期付款。

## 手续费

最低交易手续费包括：

- 每笔逻辑交易 5,000 μJTM；
- 每个有效输入 100 μJTM；
- 每个有效输出 700 μJTM；
- 每个净新增已占用槽位 2,500 μJTM，再乘以占用压力倍数。

压力倍数为：

| 父 State 占用率 | 倍数 |
|---:|---:|
| 低于 50% | 1× |
| 50% 至低于 75% | 2× |
| 75% 至低于 90% | 4× |
| 90% 及以上 | 8× |

[State 增长费](../reference/glossary.md#state-growth-fee)会被销毁。基础费、输入费、输出费以及自愿追加的手续费可由矿工领取。

把多个输入归集为一个输出会缩减 State，因此不支付 State 增长费。

## 动态转发下限

节点只会将手续费同时满足共识最低值和本地转发策略的交易纳入并转发。动态下限取 5,000 μJTM 与该节点本地内存池最近接纳的 50 笔交易之中位手续费的 90% 两者中的较大值；它不依据全网确认交易计算。

该转发下限是本地策略。共识手续费核算仍完全由交易形状和父 State 占用率确定。
